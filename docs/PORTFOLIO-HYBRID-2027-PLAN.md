## Executive decision

Upgrade the existing static HTML/CSS/JavaScript site, not its technical stack. An editorial design communicates recruiter trust; a *localized* scroll-driven explanation of controlled AI execution provides technical distinctiveness. The animation is progressive enhancement, not a prerequisite to reading the content. No unlicensed component copying, no framework migration, no new tracking, no removal of original evidence.

This is a **suitability judgment**, not a claim of independently ranking in the global top 100 websites or a forecast of conversion improvement.

## Phase execution plan

3. No modifications to `assets/docs/`, `assets/images/`, existing credential records, or original scripts other than explicitly scoped role-lens functions.
4. Define rollback as abandoning/closing the draft PR. Production remains unchanged.

### Phase 1 — Editorial design and badge cleanup (preview implemented)
1. Load Instrument Sans + Instrument Serif through Google Fonts; fallback stacks remain.
2. Introduce hybrid CSS **after** existing stylesheets, avoiding destructive base rewrite.
3. Replace polygon/octagon badge *chassis CSS only*, preserving every original badge image.
4. Improve micro-pills, role panels, ambient lighting and contrast without adding JS libraries.
5. Preserve original gold crest until a separately reviewed replacement asset is authorized.

### Phase 2 — Native scroll demonstration (preview implemented)
1. Insert a four-stage narrative before the existing AI Systems Lab: Define → Connect → Challenge → Explain.
2. Use semantic `<ol>` and readable static text, no scroll hijack.
3. Progressive CSS `animation-timeline:view(block)` with `@supports ((animation-timeline: view()) and (animation-range: entry))`.
4. Respect `prefers-reduced-motion`. Content is fully visible without animation, supported browsers or JS.
5. Keep the existing original AI globe and four lab simulations untouched.

### Phase 3 — Evidence intelligence (limited, source-safe preview)
1. Preserve the 92-entry local searchable index and full archival evidence.
2. Add direct role-specific navigation into the existing indexed library.
3. Do **not** fabricate 108+ additional credential entries, issuer dates, certifications, or employer achievements.
4. After direct read of original DOCX/PDF, create a skills-to-experience-to-evidence matrix; inspect embedded media, privacy, dates and inconsistencies.
5. Perform deduplication/issuer verification before expanding counts. Unsupported claims are removed or labeled.

### Phase 4 — Functionality and UX (preview implemented)
1. Keep role button behavior and update matching evidence URL.
2. Add ArrowLeft/ArrowRight/Home/End keyboard operation with roving tab focus.
3. Parse `?role=` on the credentials page only when it matches the available dropdown values.
4. Preserve forms, Netlify integration, four lab simulations, and all project/certificate viewers.
5. Do not install analytics, change event capture, contact routing or introduce third-party scripts beyond font delivery.

### Phase 5 — Adversarial QA and approval (pending visual/browser checks)

**Critical gates (all must pass before production):**
- Main, credentials, résumé, PDFs, and original certificate/media URLs resolve.
- Form submissions work and do not leak personal data.
- Existing lab modes, role selector, certificate dialog, search and download flows retain behavior.
- No hidden or false credential claims; simulations labeled honestly.
- Keyboard navigation, visible focus, usable one-thumb mobile view and reduced-motion behavior.
- No syntax/CSP violations, broken resource links, unreviewed third-party tracking or significant performance regression.

**Noncritical tests (target ≥95% passing only if an actual suite is executed):**
- Visual snapshots at 375/390/768/1024/1440 CSS pixels.
- Chrome, Edge, Firefox, and Safari current versions; at least one older/fallback browser.
- Dynamic keyboard and touch role-switching; role deep links including bad/empty values.
- Screenshot comparisons; overflow and text clipping; high zoom; dark-background contrast.
- Performance: LCP ≤2.5s, INP ≤200ms, CLS ≤0.1 at the 75th percentile **if field data is available**. Local Lighthouse estimates are not field-data proof.
- Recheck external link destination, PDF/DOCX integrity and internal navigation.

**Adversarial stress passes:** (1) three-second recruiter scan, (2) tired/mobile one-thumb user, (3) keyboard-only visitor, (4) reduced motion, (5) slow phone, (6) JS disabled, (7) invalid role query, (8) missing webfont, (9) false credential authority, (10) regression of forms and demos. Reproduce → patch → retest, recording actual receipts.
